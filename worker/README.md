# Воркер для стены

Маленький «посредник» на Cloudflare Workers (бесплатно). Гости пишут на стену, воркер сам коммитит
записи в `wall.json`, а граффити в папку `wall/`. Токен GitHub лежит только в воркере, на сайт он не попадает.

## Настройка (один раз, минут 10)

### 1. Токен GitHub для воркера
1. Открой https://github.com/settings/personal-access-tokens/new
2. Название: `wardrobe-wall`. Срок: на твой выбор.
3. Repository access → Only select repositories → выбери `wardrobe`.
4. Permissions → Repository permissions → **Contents: Read and write**.
5. Нажми Generate token и скопируй его (виден один раз).

Лучше сделать для воркера отдельный токен, не тот, что у тебя в админке.

### 2. Воркер в Cloudflare
1. Зайди на https://dash.cloudflare.com, заведи бесплатный аккаунт.
2. Workers & Pages → Create → Create Worker → имя `wardrobe-wall` → Deploy.
3. Edit code → удали всё, вставь содержимое файла `wall-worker.js` из этой папки → Deploy.

### 3. Переменные воркера
Settings → Variables and Secrets → Add:

| Имя | Тип | Значение |
|---|---|---|
| `GITHUB_TOKEN` | **Secret** | токен из шага 1 |
| `GITHUB_REPO` | Text | `SmokiMioki/wardrobe` |
| `GITHUB_BRANCH` | Text | `main` |
| `ALLOWED_ORIGIN` | Text | `https://smokimioki.github.io` |

`ALLOWED_ORIGIN` это адрес сайта без пути. Если сайт открывается на своём домене, впиши его.
Можно несколько через запятую.

### 4. Адрес воркера на сайт
Скопируй адрес воркера (вида `https://wardrobe-wall.твоё-имя.workers.dev`) и вставь в `config.js`:

```js
wallApi: 'https://wardrobe-wall.твоё-имя.workers.dev',
```

После этого гости пишут и рисуют, а записи попадают в репозиторий. На сайте они появляются примерно через минуту
(пока GitHub Pages обновляется), а у автора видны сразу с пометкой «ожидает публикации».

## Как это защищено
- принимает запросы только с адреса сайта (`ALLOWED_ORIGIN`);
- не больше 10 отправок за 10 минут с одного адреса;
- текст до 1000 символов, комментарий до 300, имя до 30;
- граффити только настоящий PNG до 400 КБ;
- записывает только в `wall.json` и в `wall/`, ничего другого в репозитории не трогает;
- удалять записи может только владелец: войти в админку на этом устройстве, и на стене появятся ссылки «Удалить».

## Если что-то не работает
- В журнале воркера (Logs) видны ошибки. Частая причина: у токена нет права Contents: Read and write
  или он выдан не на тот репозиторий.
- Сайт пишет «Этот сайт не разрешён»: `ALLOWED_ORIGIN` не совпал с адресом сайта.
- Пустой `wallApi` в `config.js` означает старое поведение: записи гостей остаются только в их браузере.
